## 1. Проект с высоты

Проект состоит из пяти слоёв. Каждый следующий знает только о предыдущих.

| Слой | Где лежит | За что отвечает |
| --- | --- | --- |
| Ядро симуляции | `core/include/roversim/*.hpp`, `core/src/*.cpp` | мир, физика робота, сенсоры, задача (цель, награда), пакет сред, разделяемая память, визуализация |
| Навигация | `core/include/roversim/nav/`, `core/src/nav/` | карта занятости, SLAM, планировщики, трекер подвижных объектов, DWA, навигатор |
| Биндинги | `python/bindings.cpp` | один файл: всё ядро и навигация как модуль Python `roversim._core` |
| Пакет Python | `python/roversim/` | среда Gymnasium, пакетная среда, агент навигации, удобные конструкторы |
| Приложения | `apps/`, `rl/`, `examples/`, `tests/` | сервер, бенчмарки, обучение PPO, примеры, тесты |

Главное правило разделения: **ядро симуляции ничего не знает о навигации**, а
**навигация ничего не знает об истинном состоянии мира**. Навигатор получает
только то, что получил бы настоящий робот, — скан лидара и одометрию. Истинная
поза и истинная карта используются лишь для награды, метрик и отрисовки.

Все величины — в СИ: метры, секунды, радианы, рад/с для колёс. Ось $x$ робота
смотрит вперёд, ось $y$ — влево, углы отсчитываются против часовой стрелки.

## 2. Ядро симуляции: файл за файлом

### `math.hpp` — геометрия

`Vec2`, `Pose2` (x, y, theta), повороты `rotate` / `rotate_inv`, приведение угла
`wrap_angle`, расстояния. Здесь нет логики — только типы и операции над ними.

### `rng.hpp` — случайные числа

Класс `Rng`: генератор xoshiro256++ с собственными распределениями (равномерное,
нормальное). Сделан свой, потому что стандартные распределения C++ дают разные
числа в разных библиотеках, а симулятор обязан быть воспроизводимым.
`Rng::stream(seed, id)` выдаёт независимый поток для каждого источника
случайности: выбор старта и цели, шум лидара, IMU, одометрии, подвижные
препятствия. Поэтому изменение числа лучей лидара не сдвигает шум IMU.

### `world.hpp`, `world.cpp` — мир

Класс `World` — сетка занятости плюс аналитические препятствия (прямоугольники
`Aabb`, круги `Circle`). Отвечает за три вещи:

| Что | Функция | Кому нужно |
| --- | --- | --- |
| Построение мира | `set_cell`, `fill_box`, `add_box`, `add_circle`, `finalize`; фабрики `World::arena`, `World::maze`, `World::cluttered`, `World::from_ascii` | пользователю |
| Трассировка лучей | `raycast`, `raycast_scan` | лидару |
| Столкновения | `collide_circle` (контакты круга робота: нормаль и зазор), `is_free` | физике, выбору старта и цели |

Край сетки считается стеной. После изменения клеток нужно вызвать `finalize()`:
он строит поле расстояний, которое ускоряет и лучи, и столкновения.

### `robot.hpp`, `robot.cpp` — динамика привода

`RobotParams` — геометрия, массы, параметры моторов и трения. `RobotState` —
поза, скорости корпуса и колёс. `DiffDrive::step` делает один шаг физики:
уставки колёс → моменты моторов → силы трения шин → контакты со стенами → новые
скорости и поза. `DiffDrive::twist_to_wheels` переводит пару «линейная и угловая
скорость» в уставки колёс. Вся физика робота — только в этом файле.

### `sensors.hpp`, `sensors.cpp` — сенсоры

| Класс | Что моделирует | Настройки |
| --- | --- | --- |
| `Lidar2D` | скан дальностей с шумом, потерями отражений и квантованием; видит и подвижные препятствия | `LidarConfig` |
| `Imu` | гироскоп и акселерометр, усреднённые за период управления, с белым шумом и дрейфом смещения | `ImuConfig` |
| `WheelOdometry` | энкодеры (квантование, шум) и счисление пути с ошибками калибровки | `OdomConfig` |

Сенсоры не хранят состояние мира: им каждый раз передают мир и позу робота.

### `navgrid.hpp`, `navgrid.cpp` — истинные кратчайшие пути

`NavGrid` считает по **истинной** карте проходимые клетки, поле расстояний до
цели (`distance_field`) и подсказку маршрута (`lookahead`). Используется только
«судьёй»: для награды, для подсказки в наблюдении, для метрики SPL и для выбора
достижимых старта и цели. Навигатор им не пользуется.

### `simulator.hpp`, `simulator.cpp` — симулятор

Класс `Simulator` собирает всё вместе и даёт интерфейс в стиле Gym:

| Метод | Что делает |
| --- | --- |
| `reset(seed)` | новый эпизод: старт, цель, подвижные препятствия, сброс сенсоров |
| `reset(seed, start, goal)` | то же с заданными стартом и целью |
| `step(command)` | один шаг управления (10 шагов физики), возвращает `StepResult` |
| `lidar()`, `proprio()`, `state()` | наблюдения — виды на внутренние буферы, без копирования |

Здесь же живут настройки задачи (`TaskConfig`: радиус цели, лимит шагов, веса
награды), подвижные препятствия (`ObstacleConfig`, `move_obstacles`) и раскладка
наблюдений: перечисление `obs` — индексы вектора `proprio`, перечисление `gt` —
индексы вектора истинного состояния `state`.

### `vec_simulator.hpp`, `vec_simulator.cpp` — пакет сред

`VecSimulator` держит много независимых симуляторов и шагает их в пуле потоков.
Наблюдения всех сред лежат в общих массивах `[число сред × размер]`. Завершённые
эпизоды перезапускаются сами. Результат не зависит от числа потоков. Нужен для
обучения с подкреплением.

### `shm.hpp`, `shm.cpp` — разделяемая память

`ShmServer` создаёт сегмент POSIX и выполняет команды клиента; `ShmClient`
подключается к сегменту из другого процесса. Раскладку сегмента задаёт структура
`ShmHeader` — по ней к симулятору можно подключиться из любого языка. Наблюдения
симулятор пишет прямо в сегмент, клиент читает их по указателю.

### `viz.hpp`, `viz_raster.cpp`, `viz_web.cpp`, `web/viewer.html` — визуализация

`viz::Renderer` рисует кадр сверху в массив RGB; `viz::to_ansi` превращает кадр в
цветной текст для терминала; `viz::WebViewer` — встроенный HTTP/WebSocket-сервер,
который отдаёт страницу `web/viewer.html` и шлёт ей кадры. Страница встраивается
в бинарник при сборке (`cmake/viewer_html.hpp.in`). Если визуализацию не
вызывать, симулятор о ней не знает — это и есть headless-режим.

## 3. Что происходит за один шаг симулятора

`Simulator::step(command)` получает уставки угловых скоростей колёс и делает:

1. **10 шагов физики** по 5 мс. На каждом:
   - `move_obstacles` — сдвинуть подвижные препятствия, отразить их от стен, друг
     от друга и от робота;
   - `World::collide_circle` — найти контакты корпуса со стенами; добавить
     контакты с подвижными препятствиями;
   - `DiffDrive::step` — моторы, трение, контакты, новая поза;
   - `resolve_penetration` — убрать микронное проникновение в стену;
   - `Imu::accumulate` — накопить показания IMU.
2. **Сенсоры** (`sense`): скан лидара, отсчёт IMU, одометрия, направление на цель
   и подсказка маршрута — всё записывается в буферы наблюдений.
3. **Задача**: награда (прогресс к цели минус штрафы), признаки завершения.

Итог — `StepResult`: `reward`, `terminated` (цель или столкновение), `truncated`
(лимит шагов), `collision`, `success`.

Период управления — 50 мс (`physics_dt * substeps`). Сенсоры обновляются раз в
период управления.

## 4. Навигация и SLAM: файл за файлом

Всё в пространстве имён `roversim::nav`, каталоги `core/include/roversim/nav/` и
`core/src/nav/`.

| Файл | Класс | За что отвечает | Чем НЕ занимается |
| --- | --- | --- | --- |
| `occupancy_grid` | `OccupancyGrid` | карта: клетки «свободно / занято / не разведано», встраивание скана, трассировка лучей алгоритмом Брезенхема, память «пола» и память попаданий | не знает, где робот: позу ему передают |
| `slam` | `GridSlam` | оценка позы: прогноз по одометрии, уточнение сопоставлением скана с картой, вызов картографирования | не планирует |
| `planner` | `GridPlanner` | карта стоимости (раздувание препятствий), глобальный маршрут A* или Theta* | не знает о подвижных объектах |
| `tracker` | `ObstacleTracker` | поиск подвижных объектов сравнением скана с картой, оценка их скорости | не управляет роботом |
| `dwa` | `DwaPlanner` | выбор скоростей на ближайшие 1.6 с: перебор дуг, проверка зазоров, прогноз движения объектов | не знает глобального маршрута — только локальную цель |
| `navigator` | `Navigator` | связывает всё: вызывает части в нужном порядке, решает, когда перепланировать, как выходить из застревания | сам ничего не считает |

Каждую часть можно использовать отдельно — они не зависят друг от друга, кроме
как через `Navigator`.

## 5. Что происходит за один такт навигатора

`Navigator::update(ranges, odom, odom_v, odom_w)` получает скан и одометрию,
возвращает уставки колёс. Порядок действий:

1. **Где я?** `GridSlam::localize` — прогноз позы по приращению одометрии и
   уточнение по карте.
2. **Что движется?** `OccupancyGrid::find_transient_hits` отмечает лучи,
   отражение которых пришло с «пола» (места, которое карта видела свободным);
   `ObstacleTracker::update` собирает их в объекты и оценивает скорости.
3. **Обновить карту.** `GridSlam::integrate` — встроить скан, не занося в карту
   лучи подвижных объектов.
4. **Маршрут.** Если пора (раз в 2 с, либо маршрут перекрыт, либо его нет) —
   `GridPlanner::set_map` и `GridPlanner::plan`.
5. **Локальная цель.** Точка маршрута в 0.7 м впереди робота.
6. **Скорости.** Если цель сбоку или сзади — разворот на месте; иначе
   `DwaPlanner::compute`. Если робот застрял — отъезд назад.
7. **Колёса.** Пара «линейная и угловая скорость» переводится в уставки колёс.

Состояние навигатора — `NavStatus`: `Idle` (цели нет), `Driving` (едет),
`Reached` (доехал), `NoPath` (маршрута на текущей карте нет, ждёт), `Recovering`
(выходит из застревания).

## 6. Слой Python

### `python/bindings.cpp`

Единственный файл на C++, который знает о Python. Отдаёт классы ядра и навигации
(подмодуль `roversim.nav`), а буферы наблюдений — как массивы NumPy поверх памяти
симулятора: без копирования и с защитой от записи. На время `reset` и `step`
отпускает блокировку интерпретатора.

### `python/roversim/`

| Файл | Что в нём | За что отвечает |
| --- | --- | --- |
| `__init__.py` | экспорт имён, регистрация среды `roversim/Nav-v0` | что видно после `import roversim` |
| `config.py` | `make_config`, `make_world` | настройка одной строкой: `make_config({"lidar.num_rays": 180})`; опечатка в имени поля — ошибка |
| `env.py` | `RoverEnv` | среда Gymnasium: действия «скорости» или «колёса», наблюдения словарём или вектором, отрисовка, работа через разделяемую память |
| `vec_env.py` | `RoverVecEnv` | пакет сред для обучения: наблюдения сразу на все среды |
| `navigation.py` | `NavigationAgent`, `make_navigator`, `render_navigation` | навигатор «под ключ» для симулятора или клиента разделяемой памяти; картинка «карта, маршрут, объекты» |

`RoverEnv` и `NavigationAgent` одинаково работают с симулятором в том же
процессе и с `ShmClient` — им нужны только наблюдения.

## 7. Обучение с подкреплением

| Файл | Что в нём | За что отвечает |
| --- | --- | --- |
| `rl/model.py` | `ActorCritic`, `encode_observation`, `to_env_action`, `evaluate_policy`, `save_checkpoint`, `load_checkpoint`, `make_mazes`, `DEFAULT_SIM` | всё общее для обучения и проверки: сеть, перевод наблюдений в признаки и действий сети в команды, оценка политики |
| `rl/train_ppo.py` | цикл PPO | сбор траекторий в `RoverVecEnv`, расчёт преимуществ, обновление сети, проверка на новых лабиринтах, сохранение лучших весов |
| `rl/evaluate.py` | проверка | метрики обученной политики на лабиринтах, которых не было в обучении; показ езды в браузере |
| `models/*.pt` | веса | `ppo_rover.pt` — статичные лабиринты; `ppo_rover_dynamic.pt` — обучена с двумя подвижными препятствиями |

Что видит сеть, определяет одна функция — `encode_observation`. Что сеть может
делать — `to_env_action`. Настройки среды для обучения — словарь `DEFAULT_SIM`.

## 8. Программы

Собираются в `build/`.

| Программа | Исходник | Что делает | Основные ключи |
| --- | --- | --- | --- |
| `roversim_server` | `apps/server.cpp` | симулятор как отдельный процесс: сервер разделяемой памяти либо демонстрация | `--shm`, `--world`, `--rays`, `--obstacles`, `--viz none\\|tui\\|web`, `--demo`, `--driver pursuit\\|nav`, `--spin-us` |
| `roversim_bench` | `apps/bench.cpp` | скорость ядра: один симулятор, пакет сред, задержка обмена через разделяемую память | нет |
| `roversim_nav_bench` | `apps/nav_bench.cpp` | качество навигации: успех, касания, SPL, качество карты, время такта | `--episodes`, `--only static\\|dynamic\\|timing`, `--hit-memory`, `--confirm-travel`, `--startup-time` |
| `roversim_tests` | `tests/test_core.cpp` | тесты ядра и навигации | имя теста или его часть |

`apps/autopilot.hpp` — простой водитель «по истинному кратчайшему пути» для
демонстрации и тестов; к навигационному стеку отношения не имеет.

## 9. Параметры: что крутить

Все параметры симулятора собраны в `SimConfig`. Из Python любое поле задаётся
путём через точку: `rs.make_config({"robot.mass": 8.0})`.

### Симулятор

| Хочу изменить | Параметр | По умолчанию |
| --- | --- | --- |
| Точность и скорость физики | `physics_dt`, `substeps` | 5 мс, 10 шагов → период управления 50 мс |
| Размер робота | `robot.radius`, `robot.wheel_radius`, `robot.track_width` | 0.20, 0.05, 0.30 м |
| Массу и инерцию | `robot.mass`, `robot.inertia_z`, `robot.wheel_inertia` | 10 кг, 0.20 и 0.002 кг·м² |
| Мощность моторов | `robot.motor_gain`, `robot.motor_max_torque`, `robot.max_wheel_speed` | 0.5 Н·м·с/рад, 0.6 Н·м, 20 рад/с |
| Сцепление (лёд, песок) | `robot.mu_long`, `robot.mu_lat`, `robot.rolling_resistance` | 0.8, 0.9, 0.015 |
| Число лучей и обзор лидара | `lidar.num_rays`, `lidar.fov`, `lidar.range_max` | 360, 2π, 10 м |
| Шум лидара | `lidar.noise_std`, `lidar.noise_std_rel`, `lidar.dropout_prob`, `lidar.resolution` | 1 см, 0, 0, 1 мм |
| Шум IMU | `imu.gyro_noise_density`, `imu.gyro_bias_walk`, `imu.accel_noise_density`, `imu.accel_bias_walk` | см. `sensors.hpp` |
| Качество одометрии | `odom.ticks_per_rev`, `odom.slip_noise`, `odom.wheel_radius_error`, `odom.track_width_error` | 4096, 0.002, 0.003, 0.005 |
| Условие успеха и длину эпизода | `task.goal_radius`, `task.max_steps`, `task.terminate_on_collision` | 0.30 м, 600, да |
| Награду | `task.progress_weight`, `task.step_penalty`, `task.collision_penalty`, `task.success_reward` | 1, 0.01, 5, 10 |
| Подсказку маршрута в наблюдении | `task.path_hint`, `task.lookahead` | да, 0.8 м |
| Подвижные препятствия | `obstacles.count`, `obstacles.radius`, `obstacles.speed_min`, `obstacles.speed_max` | 0, 0.20 м, 0.2–0.5 м/с |

### Навигатор

Настройки собраны в `NavigatorConfig`; заготовку под параметры робота даёт
`nav::navigator_config(robot, control_dt)`.

| Хочу изменить | Параметр | По умолчанию |
| --- | --- | --- |
| Размер и разрешение карты | `slam.map.size_x`, `slam.map.size_y`, `slam.map.resolution` | 20 × 20 м, 5 см |
| Насколько быстро карта верит и забывает | `slam.map.log_odds_hit`, `slam.map.log_odds_miss`, `slam.map.hit_memory` | 0.85, 0.40, 200 |
| Защиту стен от скользящих лучей | `slam.map.surface_clearance` | 1.5 клетки |
| Сопоставление сканов (вкл/выкл, точность) | `slam.scan_matching`, `slam.linear_step`, `slam.angular_step`, `slam.refinements` | да, 2 см, 0.01 рад, 4 |
| Насколько SLAM доверяет одометрии | `slam.prior_linear`, `slam.prior_angular` | 30, 60 |
| Алгоритм глобального планировщика | `planner.algorithm` | Theta* |

## 11. Рецепты: как сделать…

**…свой мир.** Из Python — `rs.World.from_ascii([...], cell_size)` (символ `#` —
стена) либо `rs.World(width, height, cell_size)` и `add_box` / `add_circle`. Новую
фабрику на C++ добавляют в `world.cpp` рядом с `World::maze`.

**…другой робот.** Поменять поля `robot.*` в конфигурации. Если меняется радиус —
навигатор подстроится сам, когда его создают через `navigator_config`.

**…более шумные сенсоры.** Поля `lidar.*`, `imu.*`, `odom.*`. Модель шума лидара
— функция `Lidar2D::scan` в `sensors.cpp`.

**…новый сенсор.** Добавить класс в `sensors.hpp` / `sensors.cpp`, свой поток
случайных чисел и вызов в `Simulator::sense`; новые компоненты наблюдения — в
перечисление `obs` в `simulator.hpp` (и в `python/bindings.cpp`, подмодуль `obs`).

**…другую награду.** Веса — поля `task.*`. Формула — конец функции
`Simulator::step` в `simulator.cpp`.

**…другой глобальный планировщик.** `planner.algorithm` переключает A* и Theta*.
Новый алгоритм добавляют в `GridPlanner::plan` (`planner.cpp`): карта стоимости и
проверки видимости там уже есть.

**…другое поведение у препятствий.** Целевая функция DWA и условие допустимости
траекторий — функция `DwaPlanner::compute` в `dwa.cpp`. Решения уровнем выше
(когда разворачиваться на месте, когда отъезжать) — `Navigator::update` в
`navigator.cpp`.

**…обучить политику.** `rl/train_ppo.py`; подвижные препятствия — ключ
`--obstacles N`. Чтобы изменить вход сети, правят `encode_observation` и
`ActorCritic` в `rl/model.py`.

**…посмотреть, что происходит.** В браузере: `roversim_server --demo --viz web`
или `RoverEnv(render_mode="web")`. Карту навигатора — `rs.render_navigation`.

**…подключиться из другого языка.** Запустить `roversim_server`, открыть сегмент
разделяемой памяти и читать его по раскладке `ShmHeader` из `shm.hpp`.

**…измерить, стало ли лучше.** `roversim_nav_bench --episodes 200` до и после
изменения. Различия меньше 3–4 эпизодов из 200 — шум.

## 12. Диагностика: симптом и где искать

| Симптом | Вероятная причина | Где смотреть |
| --- | --- | --- |
| Робот не едет, статус `NoPath` | маршрута нет на текущей карте: проход перекрыт или слишком узок для запаса | `planner.safety_margin`, `GridPlanner::set_map`; картинка `rs.render_navigation` |
| `set_goal` выдаёт ошибку | цель за пределами карты | `slam.map.size_x`, `slam.map.size_y` |
| Карта «плывёт», стены двоятся | сопоставление сканов не работает или выключено | `slam.scan_matching`, `GridSlam::match_score` |
| Робот крутится у стены | застревание и выход из него | `stuck_time`, раздел 4 функции `Navigator::update` |
| Робот боится проходов | слишком большой запас | `planner.soft_radius`, `dwa.safety_margin` |
| Робот задевает препятствия | мал запас или горизонт DWA | `dwa.safety_margin`, `dwa.moving_margin`, `dwa.horizon` |
| Подвижные объекты не замечаются | они вне разведанного «пола» или дальше 6 м | `tracker.max_range`, `OccupancyGrid::find_transient_hits` |
| На карте появляются «призраки» | объект попал в карту до того, как был замечен трекером | `slam.map.hit_memory`, `tracker.park_time` |
| Обучение не сходится | награда или наблюдение | `task.*`, `encode_observation`, журнал `train_ppo.py` |
| Два прогона дают разные числа | нарушена воспроизводимость | тест `simulation_is_deterministic`; флаги компилятора в `CMakeLists.txt` |
| Клиент разделяемой памяти ждёт слишком долго | сервер успел уснуть между командами | `--spin-us`, `ShmServer::set_spin_time` |
